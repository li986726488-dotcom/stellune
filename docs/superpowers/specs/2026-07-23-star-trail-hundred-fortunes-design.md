# 原创星轨百签设计

## 目标

将当前“7 个等级等于 7 支签”的实现升级为 100 支独立编号签。结构参考观音签、黄大仙签常见的“编号、签级、签诗、解曰、提醒”，但所有名称、诗句、解释和建议均为 Stellune 原创，不使用宗教名号，不宣称神谕或真实预测。

## 数据结构

每支签包含：

```text
number          1—100 的固定编号
catalog         固定为“星轨百签”
grade           上上签 / 上签 / 中上签 / 中签 / 中下签 / 下签 / 下下签
title           2—6 字意象标题
verse           原创短签诗
interpretation  面向当下状态的娱乐解读
advice          今天可以执行的一件小事
```

100 支签的标题、签诗、解读和建议必须分别唯一。

## 签级分布

参考传统百签以中签为主体、上下签较少的结构，使用：

| 签级 | 数量 |
|---|---:|
| 上上签 | 6 |
| 上签 | 16 |
| 中上签 | 20 |
| 中签 | 25 |
| 中下签 | 15 |
| 下签 | 16 |
| 下下签 | 2 |

签级不按连续编号排列。使用编号的确定性排列映射签级，保证 100 支签内数量准确，同时避免某段编号全部为同一等级。

## 抽取流程

```text
读取当天已保存签运
  -> 已存在：直接返回
  -> 不存在：
       SHA256(localDate + guestId + fortuneRulesVersion)
       -> 前 8 位转整数
       -> % 100
       -> 读取对应编号签
       -> 写入 daily_fortunes
       -> 返回
```

同一游客、日期和规则版本结果稳定。升级签库时更新 `FORTUNE_RULES_VERSION`，旧签仍保留在历史数据库记录中，新版本按新签库抽取。

## 内容安全

- 下签表达“放慢、核对、休息、求助”，不表达灾祸必然发生。
- 不涉及死亡、疾病诊断、怀孕、投资涨跌、法律结果等严肃预测。
- 不要求用户提供姓名、住址、生辰八字或具体问题。
- 页面允许主动重抽；重抽避开当前签，并覆盖保存当天最新结果。

## UI

- 翻面顶部展示“第 XX 签 · 签级”。

- 不增加重新抽取入口。

## 测试

- Rust 验证签库恰好 100 支。
- 验证编号连续、标题/签诗/解读/建议均不重复。
- 验证七个签级数量符合设计。
- 验证任意索引均映射到 1—100，且超出范围循环映射。
- Playwright 验证编号、签级和签文展示，以及重复进入仍为同一支签。
