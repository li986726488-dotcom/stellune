# 星轨百签

## 定位

星轨百签是 Stellune 的原创轻娱乐签运系统。它参考观音签、黄大仙签等传统签谱的
阅读结构：

```text
抽出编号 -> 查看签级 -> 阅读签诗 -> 阅读解曰 -> 接住一条行动提醒
```

它不属于任何寺庙或宗教传承，不复制传统签诗、神明名号和历史典故，也不把结果
描述成必然发生的预测。

## 版本

| 项目 | 当前值 |
|---|---|
| 签库名称 | 星轨百签 |
| 签数 | 100 |
| 规则版本 | `2026.07.2` |
| 权威数据源 | `src-tauri/src/domain/fortune_catalog.rs` |
| 首次抽取 | 当地日期、游客 ID、规则版本的稳定哈希 |
| 主动重抽 | 稳定字段、随机 nonce 与当前签号共同约束 |
| 保存方式 | SQLite `daily_fortunes` |

规则版本参与抽签缓存键。签库数量、顺序、内容或签级分布发生变化时必须升级版本，
避免新规则错误读取旧结果。

## 一支签的组成

```json
{
  "number": 47,
  "catalog": "星轨百签",
  "grade": "上上签",
  "title": "云开见月",
  "verse": "云移月渐明，缓步见归程。",
  "interpretation": "迟疑正在散开，真正适合你的方向会变得清晰而可行。",
  "advice": "先完成一件最重要的小事，再回应外界的声音。"
}
```

- `number`：固定为 1—100。
- `grade`：用于表达整体节奏，不代表事实结论。
- `title`：方便记忆的星夜、山水或日常意象。
- `verse`：原创短签诗，不引用现成签谱。
- `interpretation`：将意象转换成轻量情绪陪伴。
- `advice`：用户当天可以执行的一件小事。

## 签级分布

百签不是七个等级等概率抽取，而是先均匀抽取 1—100 的签号，再读取该编号的签级。

| 签级 | 数量 | 占比 |
|---|---:|---:|
| 上上签 | 6 | 6% |
| 上签 | 16 | 16% |
| 中上签 | 20 | 20% |
| 中签 | 25 | 25% |
| 中下签 | 15 | 15% |
| 下签 | 16 | 16% |
| 下下签 | 2 | 2% |

编号先经过 `(number - 1) × 37 % 100` 的排列值再映射等级区间。37 与 100 互质，
因此 0—99 会完整出现一次，既保证数量准确，也让不同签级分散在整套编号中。

## 内容原则

### 上签

强调机会、连接、开始、收获与清晰，但仍给出具体行动，避免只写空泛祝福。

### 中签

强调观察、积累、调整和日常秩序。中签是百签主体，不把普通的一天描述成失败。

### 下签

强调暂停、核对、减负、休息、求助和保留退路。即使是下下签，也不得包含：

- 死亡、灾难或报应暗示；
- 疾病诊断或治疗建议；
- 怀孕、诉讼和投资结果预测；
- 对关系、工作或人生作不可逆结论；
- 恐吓用户通过付费、仪式或重复抽签改变结果。

## 抽取与缓存

```text
seed = SHA256(localDate + guestId + fortuneRulesVersion)
index = seed 前 8 位转整数 % 100
fortune = catalog[index]
```

首次抽取后保存完整 `DailyFortune` 快照。用户可以点击“重新抽签”，重抽会加入
随机 nonce；如果计算结果恰好与当前签相同，则顺延到下一签，保证视觉上和内容上
确实发生变化。数据库按日期、游客 ID 和规则版本覆盖当天记录，重开应用恢复最后
一次结果。资料修改只重新生成今日简报，不主动改变已抽签运。

## 与大模型的边界

当前 100 支签的签号、签级、标题、签诗、解读和建议全部来自本地版本化签库，
运行时不调用大模型。未来如果加入个性化解签：

- 模型只能在固定签号和固定签意基础上润色；
- 不得修改签号、签级和原始签诗；
- 模型失败时必须回退到本地 `interpretation` 和 `advice`；
- 输入继续遵守去身份化和本地日志脱敏规则。

## 自动化检查

Rust 单元测试保证：

- 恰好 100 支；
- 标题、签诗、解读和建议分别唯一；
- 七个签级数量符合设计；
- 任意索引都循环映射到 1—100。

Playwright 首次固定使用第 47 签“云开见月”，重抽后使用第 48 签“春水绕石”，
验证编号、签级、翻牌动画、结果变化和当天最新结果恢复。
